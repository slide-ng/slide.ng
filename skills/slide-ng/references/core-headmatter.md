# Headmatter

The frontmatter of the **first slide** configures the deck. Other keys are kept and ignored, unless a theme or a component reads them.

| key                                                                                                                | meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`, `titleTemplate` (`'%s \| Conf'`), `info`, `author`, `keywords`, `lang`, `favicon`, `htmlAttrs`, `seoMeta` | the page head, see `build-seo-meta.md`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `lang`, `uiLang`                                                                                                   | `lang: tr` sets `<html lang>`, the interface language (Turkish is built in; other languages: `locales/<lang>.json`, keys in docs/UI-STRINGS.md) and the locale of `date`/`number`/`currency`; `ar`, `he`, `fa`, `ur` mirror the page, blockquote lines and the progress bar's minutes (keys stay physical; Mermaid drawings stay left to right); `uiLang` overrides the interface language only, its text keeps its own direction; to change only the interface use `uiLang`, not `--lang` (which also sets `<html lang>` and the PDF `/Lang`)                                                                                   |
| `languages`                                                                                                        | `languages: { en: slides.md, tr: slides.tr.md }`: one deck in several languages with a language menu in the bar. Each file is a deck with its own headmatter over this one's (its key is its `lang`); slides are paired by number and take the entry slide's frontmatter under their own (write `layout`, `routeAlias`, `clicks` once); keep the same number of slides in every file (a missing one shows the entry file's, an extra one is dropped, both warned); `hide:` in every file; the choice is kept in the browser and the page reloads at the same slide; `--lang tr` starts in Turkish, `export --lang tr` exports it |

## In a file of its own: `slide-ng.config.yaml`

The same keys can go in `slide-ng.config.yaml` (or `.yml`, `.json`) next to `slides.md`; each key does what it does in the headmatter. Not in Slidev.

```yaml
title: My talk
fonts:
  sans: Inter
languages:
  en: slides.md
  tr: slides.tr.md
```

- The headmatter wins key by key; `fonts`, `themeConfig`, `htmlAttrs`, `drawings` and `defaults` are merged one level deep, other objects and lists are replaced whole.
- Keys of the first slide (`layout`, `class`, `src`, `hide`, `routeAlias`, `clicks`, `dragPos`, layout props) are not read from it (a warning says so): put them in the first slide or under `defaults`. Its `title` is the deck's; slide 1's title is its heading.
- Read only from the entry file's folder; it can set what the headmatter can (`allowOutsideRoot` too), no more. With `languages` it is for every language file, and each file's headmatter still goes over it.
- Warnings name the file and line (`slide-ng.config.yaml:3: ...`); invalid YAML or JSON stops the build. `dev` watches it.
- `slide-ng.config.mjs` / `.ts` are not supported.
