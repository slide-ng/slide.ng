# Skill generation record

The agent skill in `skills/slide-ng` is written by hand from the repository's own documentation, not generated by a tool. This file
records what each file was written from, so the skill cannot silently fall behind the documents.

## How it works

- The table below lists, for every file of the skill, the repository files it was derived from.
- The JSON block records the SHA-256 of each source file (line endings ignored) at the time a person last compared the skill file with it,
  and one combined hash per skill file.
- `npm run check:skills` (`scripts/check-skills-drift.mjs`) recomputes the hashes. It exits with code 1 and lists the stale skill files
  and the changed sources when a source changed, when a skill file is not listed, or when a listed file is missing. It runs in CI.
- After a source changed: read the diff of the source (`git diff -- docs/SYNTAX.md`), update the skill files that list it, check the code
  samples with `npm run test:skills`, and only then run `npm run update:skills-hash`. That command records the new hashes. Never run it
  without re-reading the sources: it is the statement that the skill matches them.
- A new reference needs a line in the JSON block (empty hashes are fine) and a row in the tables of `SKILL.md`; then run the update command.

## Code samples

A fenced `md` block right after `<!-- verify -->` is a complete deck or slides. `npm run test:skills` (`tests/skills/verify-samples.mjs`)
generates each one in a temporary deck with the real generator (an error or a `[slides]` warning fails it), then builds all of them together
with `slide-ng build` (Angular compiles every template). `<!-- verify-file: path -->` before a fence adds a file (a component, a snippet, a
setup file, a theme file) next to the samples of the same page. Fragments that cannot stand alone carry no marker. `--each` builds every sample alone.
